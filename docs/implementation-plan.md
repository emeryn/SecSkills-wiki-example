# Implementation Plan: Wiki

Eight phases, in order. Every phase leaves `docker compose up` working on a clean clone, `make lint test scan` green, and `docs/security/threat-model.md` updated if it adds a trust boundary. Security tests from the mandatory matrix are added in the phase that introduces the feature they cover.

Design references: [architecture.md](architecture.md) (tree, data model) · [security/threat-model.md](security/threat-model.md) · [security/authentication-flows.md](security/authentication-flows.md).

## Phase 1: Foundation
**Scope:** Makefile (standard targets plus `smoke`; `admin-password` arrives in Phase 2, `screenshots` with the Playwright suite in Phase 3, `backup`/`restore-test` in Phase 5), `docker-compose.yml` from the reference (`init`, `db`, `migrate`, `backend`, `frontend`; `worker` arrives with the first scheduled job in Phase 2), Dockerfiles (numeric `USER`, distroless/slim, digest-pinned), `init` secret bootstrap (DB passwords, master key, session/CSRF keys, self-signed TLS cert, bootstrap admin password), `deploy/nginx/nginx.conf`, `deploy/postgres/`, backend app factory with `core/config.py`, JSON logging with `request_id`, DB engine over TLS with two roles, `/api/v1/health`, in-process `execve` seccomp filter, standard error format, Alembic (owner role), frontend AppShell (top bar, collapsible sidebar, breadcrumb/page header), light/dark theme, `en.json` i18n, error boundary, empty/loading/error state components, `.gitignore`, `.dockerignore`, `.env.example`, `.npmrc`, pre-commit (ruff, mypy, bandit/semgrep, eslint + security plugin, gitleaks).
**Exit:** fresh clone → `docker compose up` → HTTPS shell page on `:8443`; health green; `trivy config` clean; security headers test passes; forced-500 test returns no stack trace.
**Status:** done.

## Phase 2: Identity and access
**Scope:** local auth (Argon2id, NIST 800-63B policy, bundled breached list), equal-timing login + progressive throttling, server-side sessions (`__Host-session`, rotation, admin 1 h idle / 8 h absolute), CSRF (token + header + `Origin`/`Sec-Fetch-Site`), idempotency store + middleware, bootstrap admin (`make admin-password`, forced reset, MFA enrollment), TOTP (replay guard, hashed recovery codes), WebAuthn, password reset, step-up re-auth, session list/revoke, RBAC permission registry with deny-by-default (startup fails on undeclared route), `/api/v1/admin/*` guard, users and groups admin pages, PII column encryption for users, hash-chained audit trail + verification command.
**Tests:** route enumeration (401 / 403 / 404), mass assignment, body limit, page-size clamp, idempotency ×2, CSRF ×2, auth timing, throttling, sessions revoked on password change, reset token reuse/expiry, TOTP replay, admin without MFA, cookie flags, admin idle expiry, open redirect, password absent from logs, audit tamper detection.

**Status:** done. Deviations: outbound SMTP is opt-in (`deploy/compose.egress.yml`, no egress route by default); without SMTP, admins issue single-use reset/invitation links; the honeytoken decoy account stays in Phase 5; Radix Dialog was replaced by the native `<dialog>` because its scroll lock injects inline styles that the CSP blocks.

## Phase 3: Content
**Scope:** spaces (create, rename, archive, visibility), members (users and groups, roles), pages (tree depth ≤ 5, fractional positions, server-side slugs, move), trash (30 days, restore), revisions (every save, list, server-side diff, restore as new revision), optimistic locking (`If-Match` → `412`, missing → `428`, UI merge diff), Markdown pipeline (`markdown-it` `html: false` → DOMPurify → Trusted Types, scheme filter, no remote images, `rel="noopener noreferrer"`), split editor (toolbar, `Ctrl+S`, unsaved warning), `[[Page title]]` resolution with broken-link highlight (`page_links`), recent changes (per space, global), favorites (sidebar), dashboard page.
**Tests:** XSS corpus against the renderer (Vitest) and E2E, cross-space IDOR on every page/revision route, restricted-space titles absent from recent changes/favorites/links, admin non-member gets 404 on content, 412 flow, slug charset/length, depth limit, size limits (1 MB / 200 / 500), audit entries for membership, delete/restore, revision restore.

**Status:** done. Deviations: no `page_links` table (wiki links resolve at render time against the space's titles); space managers search users and groups through `GET /spaces/{space}/principals` (admin-only user search is not exposed to them); `GET /api/v1/auth/session` uses the general rate limit, the strict `auth` zone stays on sign-in steps; hard deletion of spaces is not implemented (archive only).

## Phase 4: Search, attachments, export
**Scope:** `tsvector` + GIN on `pages`, permission predicate joined in SQL, title matches ranked first, `ts_headline` snippets escaped then highlighted, rate limited; attachments (10 MB at Nginx and app, extension + magic bytes, Pillow re-encoding for raster images, Office/PDF/text checks, SVG/HTML refused, random storage keys on a dedicated volume, `Content-Disposition: attachment` except re-encoded images, `nosniff`), image embedding syntax; zip export of a page or space (temp dir, sanitized names, zip-slip safe, rate limited, audited, re-auth for whole space).
**Tests:** search never returns unreadable titles/snippets, snippet XSS, upload wrong magic/oversized/path in name/SVG/polyglot, zip bomb in Office files, export entry names, export audit.

**Status:** done. Deviations: legacy binary Office files (`.doc`, `.xls`, `.ppt`) are refused (macros cannot be detected), Office Open XML and OpenDocument are accepted; GIF uploads are stored as PNG (first frame); search uses the `simple` configuration; ClamAV is not integrated (optional). Migration 0004 also creates the two circular foreign keys that 0003 declared but never emitted.

## Phase 5: Administration and operations
**Scope:** admin dashboard (usage, errors, honeytoken alerts, blocked IPs), settings pages: remote syslog (RFC 5424/5425, bounded buffer), SMTPS, webhooks (HMAC-signed), all SSRF-validated with "Send test" and throttling; PII masking toggle; audit viewer (filters in URL, CSV export with formula-injection escaping, export audited); honeytokens (decoy account + trap endpoint, trusted proxy count, unblock UI); `worker` jobs: trash purge, inactive account disabling, expired sessions/tokens/idempotency keys, encrypted daily backups with separate key; `make backup` / `make restore-test`; embedded help from `docs/help/` (user and admin), `(?)` per page.
**Tests:** SSRF (`169.254.169.254`, `127.0.0.1`, DNS rebinding, redirects), CSV `=CMD()`, honeytoken blocks IP + critical audit, purge job leaves non-expired data, restore-test round trip.

**Status:** done. Deviations: backups are logical (`COPY` through the database driver, chunked AES-256-GCM, key `app/backup.key`) rather than `pg_dump`, since the images have no shell and `execve` is denied; sessions, idempotency keys, throttling and reset tokens are not backed up; migration 0005 makes the two circular foreign keys deferrable for restores and lets the runtime role read `alembic_version`. `outbound_url.py` lives in `core/` (the mailer depends on it). Notification recipients and triggers are their own settings section; `BACKEND_SMTP_*` makes the email section read-only (the Phase 6 environment precedence, applied to SMTP only). PII masking covers logs, syslog and notifications, not the audit viewer. Syslog forwarding and notifications are not installed in the test environment. The sidebar has 8 top-level entries (blueprint maximum: 7).

## Phase 6: SSO
**Scope:** OIDC (code + PKCE, `state`/`nonce`, JWKS, `alg` pinned), LDAPS/StartTLS (verified certs, escaped filters), group-to-space-role mapping (`space_members.source = sso`), auto-provisioning, shared Pydantic schema for env loader and admin API, env-defined settings read-only with "Managed by environment" badge, write-only secrets (`••••last4`, `*_FILE`), "Test connection", every change audited, `.env.example` + README table, break-glass local admin (optional). Threat model updated (IdP/directory boundary).
**Tests:** env-defined setting update → 409, secrets never returned, invalid `BACKEND_OIDC_*` fails startup, state/nonce mismatch rejected, LDAP injection payloads escaped, callback works with `SameSite=Lax`.

**Status:** done. Deviations: SSO accounts become global administrators only through administrator groups (`admin_groups`), re-synchronized at each sign-in, and still need the wiki's second factor; break-glass is the `local_sign_in = admins_only` security setting, each local administrator sign-in then raising a critical alert. Step-up for OIDC accounts re-authenticates at the IdP (`prompt=login`, `max_age=0`, fresh `auth_time`); directory accounts confirm with their directory password. Groups map to space roles only. Secrets set by environment are files mounted with `deploy/compose.sso.yml`. LDAP uses `ldap3` (pure Python, fits the distroless image); group entries are read with the service account. OIDC was tested against an in-process provider (real RSA keys and JWT validation), LDAP against ldap3's mock and a disposable OpenLDAP (LDAPS and StartTLS); neither against a production IdP.

## Phase 7: Ask the wiki (RAG)
**Scope:** `LLMProvider` interface with Ollama driver (OpenAI-compatible driver stub only if requested), model discovery, admin LLM settings (URL SSRF-validated with explicit private allowlist, internal CA bundle, proxy, parameters, token caps), embeddings per chunk on save (worker), chunks carry `space_id`; retrieval query joins the readable-spaces predicate **inside** the vector query; chunks and embeddings deleted with the page/trash purge; SSE streaming (`proxy_buffering off`), cancel, retry before first token only; answers rendered through the same sanitizer, sources listed as links to readable pages; editable versioned system prompt with reset (`backend/app/llm/prompts/`); per-user rate limit and token quota; prompts not logged by default. Threat model updated (LLM boundary, prompt injection via page content).
**Tests:** user never receives chunks or sources from unreadable spaces, injected page content cannot change instructions/tools, remote image in answer not loaded, inference URL SSRF cases, stream cancel closes upstream.

**Status:** done. Deviations: embeddings in PostgreSQL with pgvector (built into the database image from a checksum-verified source, marked trusted so the owner role creates it); no ANN index because the dimension depends on the model: retrieval is an exact scan restricted to readable spaces. Conversations are not stored (the browser sends the last three exchanges). Models are approved by pinning their digest when the settings are saved instead of a `deploy/models.lock` file. LLM settings are UI-only (no environment variables). Optional Ollama in `deploy/compose.llm.yml` (rootless, internal network, fixed subnet to allowlist). Embeddings are not backed up (rebuilt by the worker). Verified end to end with Ollama 0.34.4, `qwen2.5:0.5b` and `all-minilm`. The sidebar now has 9 top-level entries.

## Phase 8: MCP
**Scope:** user MCP `/mcp` (`search_pages`, `read_page`, `create_page`, `update_page`) authenticated by API key, same services, RBAC, validation, idempotency and `If-Match` semantics as REST; API keys (≥ 32 bytes, SHA-256 hash, prefix, scopes, expiry, revoke, last used) in account settings; admin MCP `/mcp/admin` disabled by default, toggled in admin LLM/MCP settings, admin-scoped key, `confirm` argument on destructive tools; Streamable HTTP behind Nginx, `Origin` validated, per-key rate limit; every tool call audited (key ID, tool, masked args, status, duration). Threat model updated.
**Tests:** route/tool enumeration with unauthorized keys, cross-space IDOR via tools, revoked/expired key, admin MCP off by default, destructive tool without `confirm` refused, audit row per call.

**Status:** done. Deviations: the protocol subset is implemented in the backend (no MCP SDK dependency): stateless Streamable HTTP, JSON responses, `initialize`/`ping`/`tools/list`/`tools/call`, `GET` answers 405 (no server-initiated stream); verified with the official Python SDK 2.3 (protocol 2025-11-25). MCP settings are their own section (user endpoint on, admin endpoint off by default). Admin tools manage users' sessions and blocked IPs and read the audit trail; no tool deletes pages. The interoperability check revealed that generated certificates lacked key identifiers, refused by strict clients (Python 3.13+): the bootstrap now adds them and renews older certificates automatically (restart `db` and `frontend` after the `init` run so they load them).
